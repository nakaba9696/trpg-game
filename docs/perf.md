# 動作の重さ・待ちの記録

測る道具（どちらも Playwright。重いので CI では回さない）：
- `node tools/build.mjs && node tools/perf.mjs [--slow] [--profile]` … 起動・手番・戦闘・図鑑・場面の切り替え・放置中の、処理の時間と Long Tasks・メモリ。
- `node tools/build.mjs && node tools/perf_waits.mjs [--net fast|slow|none] [--slow]` … プレイヤーが**待たされる**所（初回ロード・開始直後の背景・初めて会う人の立ち絵・初めての戦闘の魔物の絵・長く遊んだときの増え方）を、回線を絞って測る。fast＝下り 10Mbps・往復 40ms、slow＝下り 1.6Mbps・往復 150ms。

| 長く遊ぶ（150 手番） | — | JS 14〜15MB・DOM 3〜3.6 千・ログの行 90・保存 13KB で頭打ち | 同じ |

- **初回ロード**は、ほぼ `game.js`（10.7MB）を読む時間。gzip なら 3.0MB になる。公開先（Artifact）が圧縮して送っていれば、10Mbps で 2.4 秒ほど。圧縮しているかはこちらから確かめられない。読み込み中は「読み込み中…」を出す（T3。前は白紙に押せない「トロフィー」だけだった）。
- 長く遊んでも、メモリ・DOM・ログの行（90 行で打ち切り）・保存の大きさは増え続けない。
- U13（一手ずつの表示・結果の場面）・U14（場面の切り替え）のあと、1 手番・戦闘の 1 手・場面の切り替えの処理の時間は #264 の時から増えていない（場面の切り替えの中身はほぼ背景の絵を描く時間）。

## まだ大きいもの
- `game.js` の大きさ（10.7MB。ほとんどが出来事・依頼の文章）。コメントと字下げを除いても 1 割ほどしか減らない。文章のデータを場面ごとに後から読む形にすれば減るが、作りが大きく変わる。
- スプライトの SVG は画像を base64 で中に入れているので、元の webp より 3 割ほど大きい（まとめることで 1 つの版の 511 ファイルに収めている。今の形は保つ）。
